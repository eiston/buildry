# Buildry UI review — November 9, 2026

The review found 32 concrete issues: 22 addressed in this pass and 10 remaining. This is a visual and navigation audit, not a claim that every conditional business flow has been tested.

## Coverage

The isolated review instance on port 8089 was used with owner, tenant, admin, and fresh-user accounts. No property, room, lease, or personal profile content was saved during the review. Main database contents were not edited.

The main sweep captured 30 routes at 1440 × 1000 and 390 × 844. After changes, 28 authenticated routes were re-captured at both widths, with no document-level horizontal overflow. Additional checks used 805 × 737 and 320 × 740, populated rentals, property/room/task/lease details, sharing, administration, public stay details, onboarding, authentication, and mobile navigation.

## Validation and limits

- Release web build, WASM check, native backend build, and 47 backend unit tests passed; two database tests were not run in this UI-only pass.
- Authenticated existing-room and new-room page requests returned HTTP 200 after the route repair.
- Screenshots and DOM measurements verify the restored task width, contained phone calendar scrolling, visible account fields, compact tablet rail, 320 px permission controls, app empty search, and mobile sign-out.
- Test accounts were used without submitting a lease signature, sending mail, creating bills, or changing resource permissions.
- Stripe and outbound email are not configured on this review instance. Successful checkout, bank verification, outbound mail, and real payment history were not visually verified.
- New lease/template/task wizard screenshots cover their initial step. This pass does not certify every later wizard step, every validation message, every photo-ID state, or private booking-management token state.

The next design pass should start with the two phone grids and the property/task empty-field rhythm, then consolidate authentication, avatar upload, and PDF reading. The fixes here restore shared behavior; they do not replace those remaining design decisions.
